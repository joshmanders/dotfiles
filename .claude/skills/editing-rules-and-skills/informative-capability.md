# Informative / Capability Work

Documents a tool, command, workflow, or process. No incident; don't invent one.

## Shape

Calm reference: tables, code blocks, short labeled sections, examples. No `**Why:**` lines, no "non-negotiable" callouts; bold only key terms. Siblings to match:

- `github`: CLI tables by domain, each entry a labeled code block
- `bin-scripts`: `script | usage | purpose` tables grouped by purpose
- `brainstorming`: process steps in short bullet groups, principles at the end
- `dispatch-parallel-agents`: process, ❌/✅ examples, when-not-to-use
- `humanize`: pattern catalog with Before/After pairs

## Rules

- **Verify every fact.** Run the command, read `--help` or the source. Omit or ask about anything you can't verify.
- **No padding.** Lead with the table, command, or example. No preambles or philosophy sections.
- **Emphasis only for repeat offenders.** An item Josh has had to re-remind about can get a small emphatic note; the rest stays calm.

## Process

1. Confirm scope and depth with Josh.
2. Verify every fact.
3. Match a sibling skill's structure.
4. Pick global or project per `placement.md`.
5. For a new skill, present one section's draft and wait for validation before the rest.
